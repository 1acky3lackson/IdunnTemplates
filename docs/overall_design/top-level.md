# Idunn Template

## 系统目标

当玩家在Minecraft建筑服务器中使用制作好的模板后，以往的方法中模板是静态的，无法在模板更新后在其实例中应用更新。本系统对每个模板维护一个版本列表和实例列表。当模板的版本更新后，实例会相应的获得更新。

玩家可以通过将一些模板列表绑定到一个物品上形成笔刷，从而快速放置模板。笔刷可以选择是否随机旋转（归约到90°）和翻转。一个笔刷可以添加若干个目录，而其模板将从目录下（递归的）所有的模板中随机选择，以提供最大的便利性。

模板更新时，仅对 **当前世界中该坐标位置等于旧版本中该坐标位置**，或 **当前世界中该位置为空气** 的方块进行更新，以便避免破坏现有的非旧版本模板中的其他建筑内容（例如玩家手动修改的部分）。

本插件旨在和 WorldEdit 紧密衔接，允许玩家放置模板后使用 WorldEdit 的 undo 指令撤回（需通过插件监听 WorldEdit 事件实现元数据同步删除）。

## 模板

模板指的是某个世界的一个立方体（cuboid）区域。玩家通过 WorldEdit 选区创建。模板需要指定存储的路径。模板的存储文件格式类似：

``` file
<template_base_dir>/dir1/dir2/.../_<name>/<version>.schem
```

其中 `name` 表示的是玩家存储时提供的名称，前面的 `_` 标识这个文件夹为模板。`version` 是版本的版本号，为版本提交时的时间戳（毫秒，base64），以此区分新旧版本。

模板保存需要特定的权限 `idunn.template.save.personal`。玩家的模板默认保存在 `<template_base_dir>/users/<PLAYERNAME>/<user_provided_path>/_<name>/<version>.schem ` 中，避免用户之间的冲突。

如果用户指定保存在其他的顶层文件夹，则需要具有文件夹对应的权限 `idunn.template.save.<path, split by . instead of />`。如果玩家具有父目录的权限，则子目录的权限也递归的具有，不需要显式地给予。

模板的文件夹（`<template_base_dir>/dir1/dir2/.../_<name>/`）中还应当有一个 `metadata.json`，其中记录模板的元数据，包括：

*   **基本信息**:
    *   创建的玩家 ID
    *   创建时间
    *   模板所在世界 ID
    *   **模板基准点 (Anchor Point)**：创建时选区 Cuboid 的最小坐标点 (minX, minY, minZ)。此点作为模板的定位锚点，后续旋转、翻转均相对于此点（或用户指定的中心）进行。
    *   删除时间戳（软删除用，有效则为空）
*   **尺寸信息**:
    *   模板基准点相对于模板几何中心的偏移量（用于高级旋转算法，可选）
    *   边界框大小 (Width, Height, Length)
*   **版本列表**:
    *   版本号（base64时间戳）
    *   版本提交玩家 ID
    *   提交附带的 message
    *   （实际的 .schem 文件存储在文件系统中，此列表用于索引）

## 实例

模板经过玩家放置则成为实例。实例是模板应用的产物。实例的信息包括：

*   **状态信息**:
    *   删除时间戳（软删除用，有效则为空）
    *   放置玩家的 PlayerName
    *   放置时间戳（毫秒）
    *   当前版本号
    *   是否自动更新（默认为是）
*   **位置与变换**:
    *   世界 ID
    *   **基准坐标**: 模板的 **模板基准点** 在当前世界中的绝对坐标。
    *   旋转: 相对于基准坐标的旋转角度 (0, 90, 180, 270)。
    *   翻转: 相对于基准坐标的翻转状态 (Boolean, x/y/z 轴)。
    *   偏移量: 额外的微调偏移 (x, y, z)。
*   **更新历史**:
    *   更新记录列表（时间戳、旧版本号、新版本号、触发玩家）。
    *   当前世界的玩家名称列表（按离基准坐标距离排序）。

### 实例存储

实例信息作为列表保存在 JSON 文件中。为了优化性能，采用空间分区存储：
*   每相邻的 8x8 个区块（Chunk）组成一个**分区组 (Partition Group)**。
*   根据实例的 **基准坐标** 决定其归属的分区组文件。
*   文件名示例: `instances/world_name/r.x.z.json`。

**加载机制**:
当某个分区组内的任意一个区块被加载时，插件应**异步**读取对应的 JSON 配置文件，并将其中尚未加载的实例元数据载入内存缓存。

**权限**:
*   放置实例: `idunn.instance.new.<path of template>`
*   触发更新: `idunn.instance.update.<path of template>`

## 实例更新

当世界中区块加载时，插件应当检查 **基准坐标** 位于该区块内的实例。
*   如果实例设置了自动更新，且模板有新版本 -> **自动更新**。
*   如果实例设置不自动更新，但有新版本 -> **通知玩家**。

### 更新的逻辑 (Conservative Update)

系统需对比 **旧版本模板** (Old) 和 **新版本模板** (New) 以及 **当前世界方块** (Real)。

**闲置方块**: 认为 water、air 和 lava均属于闲置方块

**遍历范围**: 
取 [旧版本变换后的包围盒] 与 [新版本变换后的包围盒] 的并集。

**比对规则**:
令 P 为当前遍历的世界坐标。
*   `bo`: 实例 **旧版本** 模板中，经过翻转、旋转、偏移后，对应坐标 P 的方块。
*   `bn`: 实例 **新版本** 模板中，经过翻转、旋转、偏移后，对应坐标 P 的方块。
*   `br`: **当前世界** 中坐标 P 的方块。

**执行动作**:
1.  **判定是否为“未修改”**: 如果 `br == bo` (类型和 BlockData 一致)，说明玩家未修改该位置。
    *   -> 将 P 点方块更新为 `bn`。
    *   *(注: 对于容器类方块，建议仅比对类型和状态，忽略 Inventory NBT，以免因物品变动导致无法更新)*
2.  **判定是否为“闲置空地”**: 如果 `br == Air` 且 `bn != Air`。
    *   -> 将 P 点方块更新为 `bn`。
3.  **其他情况**:
    *   如果 `br != bo` (玩家修改过，例如把木头换成了石头)，则 **不更新**，保留玩家的修改 (`br`)。
    *   如果 `bn == Structural_Void` (结构空位)，则 **不更新**，该位置由玩家自由发挥。

**更新后**:
更新实例数据，写入更新记录，修改当前版本号。

## 模板新版本提交

玩家站在模板范围内，通过 `/idunn commit <message>` 提交。
1.  **前提**: 玩家需在模板原先划定的范围内（或自动吸附到最近的模板）。
2.  **流程**:
    *   保存新的 `.schem` 文件。
    *   更新 `metadata.json` 添加新版本记录。
    *   **触发热更新**: 遍历当前服务器所有已加载的区块。如果某区块包含某实例的基准点，且该实例对应此模板 -> 立即执行更新逻辑。

## 实例删除

实例默认不会被彻底物理删除，而是标记为“软删除”。

### 一、WorldEdit 撤销 (Undo)
如果玩家使用 WorldEdit 放置了实例，通过 `//undo` 撤销时，插件需尝试拦截或监听该操作（如果技术上可行），同步删除实例的元数据记录。
*   *技术备注*: 若无法完美拦截 WE Undo，应提供 `/idunn undo` 指令作为官方回退手段。

### 二、指令手动删除
用户通过指令删除实例。
*   **选项 A (仅断开链接)**: 将实例标记为软删除 (无效)，但不改变世界中的方块。
*   **选项 B (彻底删除)**: 将实例标记为删除，并根据“更新逻辑”中的逆向逻辑，尝试移除属于实例的方块（即 `br == current_template_block` 的方块设为 Air）。

**权限**:
*   删除自己的实例: `idunn.instance.delete.self`
*   删除他人的实例: `idunn.instance.delete.player.<playername>` 或 `idunn.instance.delete.world.<world_id>`

## 模板删除

模板不允许“硬删除” (从磁盘移除文件)，只允许“软删除” (标记为不可用)。这保证了依赖旧版本模板的实例不会崩溃。

**权限**:
*   `idunn.template.delete.self`
*   `idunn.template.delete.player.<playername>`
*   `idunn.template.delete.dir.<path>`
