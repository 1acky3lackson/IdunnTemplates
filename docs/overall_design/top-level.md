# Idunn Template

## 系统目标

当玩家在Minecraft建筑服务器中使用制作好的模板后，以往的方法中模板是静态的，无法在模板更新后在其实例中应用更新。本系统对每个模板维护一个版本列表和实例列表。当模板的版本更新后，实例会相应的获得更新。

玩家可以通过将一些模板列表绑定到一个物品上形成笔刷，从而快速放置模板。笔刷可以选择是否随机旋转（归约到90°）和翻转。一个笔刷可以添加若干个目录，而其模板将从目录下（递归的）所有的模板中随机选择，以提供最大的便利性。

模板更新时，仅对 当前世界中该坐标位置等于旧版本中该坐标位置，或 当前世界中该位置为空气 的方块进行更新，以便避免破坏现有的非旧版本模板中的其他建筑内容。

本插件和Worldedit可以紧密衔接，允许玩家放置模板后使用worldedit的undo指令撤回。

## 模板

模板指的是某个世界的一个立方体（cuboid）区域。玩家通过Worldedit选区创建。模板需要指定存储的路径。模板的存储文件格式类似

``` file
<template_base_dir>/dir1/dir2/.../_<name>/<version>.schem
```

其中 name 表示的是玩家存储时提供的名称，前面的 _ 标识这个文件夹为模板。version 是版本的版本号，为版本提交时的时间戳（毫秒，base64），以此区分新旧版本。

模板保存需要特定的权限 `idunn.template.save.personal`。玩家的模板默认保存在 `<template_base_dir>/users/<PLAYERNAME>/<user_provided_path>/_<name>/<version>.schem ` 中，避免用户之间的冲突。

如果用户指定保存在其他的顶层文件夹，则需要具有文件夹对应的权限 `idunn.template.save.<path, split by . instead of />`。如果玩家具有父目录的权限，则子目录的权限也递归的具有，不需要显式地给予。

模板的文件夹（`<template_base_dir>/dir1/dir2/.../_<name>/
`）中还应当有一个 metadata.json，其中记录模板的元数据，包括：

* 是否有效（软删除用）
* 创建的玩家的 id
* 创建时间
* 模板所在世界 id
* 模板位置中心（创建时选择 cuboid 框 x y z 坐标最小的点，此后不再变动）
* 模板坐标最小的顶点相对于模板中心位置的偏移量（初始均为0，后续若扩大缩小模板区域则可能不是0）
* 模板坐标最大的顶点相对于模板中心的偏移量
* 版本列表，最终版本以文件系统中为准，此列表仅用来记录数据信息，包括
  * 版本号（base64时间戳，暗含提交时间信息）
  * 版本提交玩家 id
  * 提交附带的 message

## 实例

模板经过玩家放置则成为实例。实例是模板的应用的产物。实例的属性有

* 是否有效（软删除用）
* 模板坐标
* 世界id
* 基准坐标（模板的 模板位置中心 所在当前世界中的坐标，翻转和旋转前）
* 旋转（相对于基准坐标的旋转）
* 翻转（相对于基准坐标的翻转，布尔值，存储 x y z 三个轴的分量）
* 偏移量（ x y z 轴，相对于基准坐标）
* 放置玩家的 playername
* 放置时间戳（毫秒）
* 当前版本号
* 是否自动更新（默认为是）
* 更新记录列表，每一项包括
  * 更新时的时间戳（毫秒）
  * 旧版本号
  * 新版本号
  * 触发更新的玩家（可以为空）
  * 当前世界的玩家名称列表，按照离基准坐标的远近从小到大排序

实例信息作为列表保存在json文件中，每相邻的 8*8 个区块的信息保存在一个文件中，通过整除算法来分配组。当组中的任意一个区块被加载，则将这个配置文件读入。

实例的放置需要对应模板的放置权限 `idunn.instance.new.<path of template, split by . instead of />`。父文件夹的权限可以递归的作用于子文件夹。如果更新由玩家触发，那么玩家需要具有触发更新的权限 `idunn.instance.update.<path of template, split by . instead of />`。

## 实例更新

当世界中区块加载时，插件应当检查基准坐标在该区块内的实例。如果实例设置了自动更新，且模板有时间戳更新的版本，那么启用下面的更新逻辑进行更新。如果实例设置不自动更新，但有新版本，那么应当在聊天栏提醒玩家注意模板的新版本，以便手动决定是否更新。

### 更新的逻辑

遍历范围：经过翻转、旋转、偏移后，新版本和旧版本的范围的并集。

（==表示方块种类和方块状态完全相同）：

* 实例的旧版本模板经过实例记录的翻转、旋转、偏移后，对应坐标 P 的方块为 bo
* 实例的新版本经过实例记录的翻转、旋转、偏移后，对应坐标 P 的方块为 bn
* 世界中所在坐标 P 的方块为 br
* 如果 br == bo 那么更新位置 P 的方块为 bn
* 如果 br == air 且 bn !== air，那么更新位置 P 的方块为 bn
* 否则不更新

更新后应当更新实例的数据，添加一条版本更新记录，并修改实例的当前版本号。

## 模板新版本提交

玩家站在模板范围内，通过 `/idunn commit <message>` 来提交。如果玩家不在模板范围内，则需先传送到范围内再提交。提交后将保存新的 schem，并更新元数据。提交后，将启动更新流程，遍历对应世界现在加载的区块，如果加载区块中有此模板的实例（基准坐标在该区块内），那么对这些实例进行更新，不必等待下一次区块加载。

## 实例删除

实例不会自动被删除，只能被玩家手动删除。玩家手动删除实例的方式是

### 一、玩家放置实例（指令或笔刷）

后通过undo撤销，则在删除实例内容的同时，删除实例的记录。这种删除会彻底删除记录。

### 二、用户通过指令手动删除实例

此时需要用户提供参数是否一起删除实例的方块（通过更新逻辑来判定一个方块是否属于实例），还是仅删除和模板的连接。如果用户选择删除记录且删除方块，那么可以将实例记录删除；若用户选择仅删除同模板的链接，那么记录将被标记为无效（软删除），而不删除记录本身。

这种情况下，玩家删除自己的实例需要具有权限 `idunn.instance.delete.self`，若是对其他的创建的实例，需要具有 `idunn.instance.delete.player.<playername>` 或 `idunn.instance.delete.world.<world_id>`。

## 模板删除

所有模板不允许硬删除，如果玩家选择删除，那么应当将模型标记为无效，从而软删除。

玩家删除自己的实例需要具有权限 `idunn.template.delete.self`，若是对其他的创建的实例，需要具有 `idunn.template.delete.player.<playername>` 或 `idunn.template.delete.dir.<path_of_dir, split by . instead of />`（父级文件夹权限覆盖子级）。
