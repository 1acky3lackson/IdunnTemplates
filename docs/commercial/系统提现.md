# Idunn 系统提现流程设计

## 功能描述

允许用户对账户余额发起提现，管理员审批后使用第三方平台转账，转账后上传转账记录，用户确认收款后，流程结束。补充流程：用户发起提现后，管理员如果审批拒绝，则提现的金额退回用户的系统账户。

## 主要流程

a. 用户提出申请。创建新的提现记录，金额为提现金额，状态为 CREATED；用户账户创建流水记录，为出账，金额为提现金额，备注为用户提现

b. 管理员审批。管理员将收到新的提现审批提醒，审批通过后，提现记录状态转为 APROVED。

c. 管理员转账。对于 APROVED 状态的请求，管理员将收到转账提醒。在给用户转账后，管理员在系统中提交转账凭证（平台+交易单号等），记录提交时间，提现请求状态变为 PAID。

d. 用户收到转账后，在系统中点击确认，请求流程结束，状态变为 FINISHED。



## 补充流程

1. 请求创建后，在 CREATED 状态中，管理员审批若拒绝，则状态转为 REJECTED，要提供说明（拒绝说明），系统记录拒绝时间。此时请求中的金额退回用户账户，创建一个新的入账记录，备注为提现退回+理由。
2. 管理员转账后，若用户未受到，则可以将 PAID 状态的请求修改为 ERROR 状态，需要附带说明。
3. ERROR 状态的请求由管理员和用户私下沟通解决。
4. 若沟通结果为放弃这次请求（比如用户不想要或者第三方转账故障等，也就是实际没有转账，想要结束流程），则管理员将状态从 ERROR 改为 REJECTED，要提供说明（错误处理说明），系统记录拒绝时间。此时请求中的金额退回用户账户，创建一个新的入账记录，备注为提现退回+理由。
5. 若沟通结果为交易成立（比如用户误触或者沟通后已解决），则用户或管理员可以将 ERROR 状态改为 FINISHED，需要提交说明（错误处理说明）。

特别注意：其他未说明的状态转换途径均不合法，应当禁止。

## 新增接口

1. 提现记录接口 /api/v1/commercial/withdraw...，RestFul 风格，支持全局列表、我的列表、单独详情、创建新的，流程中状态转换对应的各个更改接口，不支持任意修改和删除。通过 LuckyPermAuthService 校验权限，普通用户只能看到自己发起的提现记录以及发起提现，以及上面说明的状态转换，管理员可以发起全部。注意：上面未说明的转换均不合法，即时具有权限的用户操作也应当认定是非法的，予以拦截。



## 前端入口

1. 新增提现记录页面，展示提现记录列表，支持筛选搜索排序等功能，同之前订单等页面一致，后端接口风格和格式也要一致。
2. 在 /me 页面中新增提现发起入口，和我的提现记录列表（使用我的列表接口）。
