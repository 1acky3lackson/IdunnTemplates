# 递归/嵌套模板

功能旨在让玩家可以在模板中使用其他模板。一些经典的场景是：

* 我们有一些树的模板，我们在做一个建筑模板时，希望在模板中使用这些树
* 我们有一些建筑构件（比如斗拱）的模板，希望在建筑模板中引用这些建筑构件

## 触发

当玩家在模板（Template）的母版区域中放置模板时（也就是模板放置的时候检查放置的区域和任何模板的母版区域是否有交集）。如果有交集，那么取消这次放置，然后查找所有有交集的母版（可能不止有一个有交集），然后询问玩家：

``` plaintext
> 你尝试在其他模板的母版区域中放置模板，请确认：
  * 模板 [user/jacky/trees/1]: [->TP] [->确认]
  * 模板 [user/jacky/trees/2]: [->TP] [->确认]
  * 模板 [user/jacky/trees/3]: [->TP] [->确认]
  ......
```

其中 `[user/jacky/trees/1]` 是有交集的母版，`[->TP]` 可以让玩家传送到这个模板的母版处，方便玩家确认，而 `[->确认]` 则点击就会放置模板（通过 `/idunn place` 指令）。这个放置会使用 mask，确保子模板示例只在父模板的区域中出现。同时这个放置可以撤销和重做，我们需要添加一个新的历史记录类型（在父模板中放置子模板）。

## 数据问题

在父模板和子模板中，都需要记录（父模板中记录所有子模板，子模板中记录所有父模板）。一个模板可能同时是父模板和子模板。子模板记录父模板、父模板记录子模板时，均需包含所有的 Instance 信息，以便更新时候强制更新，而不用查找全部 Instance。

## 更新问题

当子模板更新后，延迟几个tick，强制更新其父模板处的 Instance，然后为父模板自动提交一个新版本（message写明是哪个子模板更新引起的），之后类似地向上层更新。
