# 嵌套模板 V2

在当前的 V1 中，我们的模板的子实例在放置后会立即触发级联更新，但这会导致撤回、重做难以实现，同时不符合用户习惯。因此我们将操作和用户接口重新设计为 V2。

V2 中，用户在放置子实例的时候，会获得类似 Git 的体验。其核心原理是：

* 在模板中 Place 实例的操作仍然需要确认
* 确认后，实例并不立即被写入父模板及子模板的父子关系字段中，而是储存在一个暂存区
  * 暂存区的意思是，这些子实例还没被玩家确认需要保存
  * 暂存区会被序列化到磁盘上单独的文件中，保存全量的 子实例-父模板 的关系
* 为了防止意外触发的级联更新将暂存区的内容更新到父模板，因此为模板设置一个锁
  * 默认为 false，此时同现在一样，级联更新自动地、静默地进行，这是绝大多数模板的状态
  * 当玩家确认了在某个模板内放置实例（实例进入暂存区），而此时这个模板的锁翻转为 true
  * 锁为 true 的模板不会被级联更新（也不会向上层传播级联更新），因为这个模板还没有被玩家确认编辑好
* 暂存区的实例可以被 undo 和 redo
  * 在 IdunnHistoryWrapper 中新增一个历史记录种类，代表这种子实例，数据中要添加父模板的信息
  * 这个新历史记录在undo时，需要一并清理暂存区的记录，同时也要像之前的实例放置历史记录那样，清除实例的数据（这部分复用代码）
  * 在 redo 时，除了需要恢复实例记录，还需要恢复暂存区记录
* 当玩家对这个模板 Commit 时，依次进行以下步骤
  * 将与这个模板相关的暂存区记录添加到父模板和子模板的父子关系字段中
  * 清空暂存区的相关记录
  * 检查所有子实例是否更新到最新版本，若没有，则强制更新
  * 提交新版本，并触发向上层的级联更新
* 为了减少被锁而且被遗忘，导致得不到更新的模板数量，我们需要提醒玩家
  * 在母版的 bossbar 中加入关于是否被锁的提示
  * 放置模板是，如果模板被锁，则用 title 提示玩家联系模板所有者，让他更新这个模板以免被锁
