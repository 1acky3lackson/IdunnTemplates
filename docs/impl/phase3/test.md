# Phase 3 Test Procedures

本文档描述了 Phase 3 (核心更新算法) 的手动测试流程。

## 1. 准备工作

*   确保服务器已安装 `IdunnTemplates` 和 `WorldEdit` (或 FAWE)。
*   确保拥有 OP 权限或 `idunn.*` 权限。
*   在 `config.yml` 中检查 `idle-blocks` 配置（默认包含 air, water, lava 等）。

## 2. 测试场景 A: 基础更新 (无冲突)

**目标**: 验证模板更新能正确同步到实例。

1.  **创建模板**:
    *   选区一个简单的房子 (包含石头和木板)。
    *   `/idunn save house1`。
2.  **放置实例**:
    *   移动到旁边。
    *   `/idunn place users/<player>/house1`。
    *   确认房子已生成。
3.  **修改模板**:
    *   回到原选区。
    *   在房子里加一个钻石块 (Diamond Block)。
    *   复制选区 (`//copy`)。
4.  **提交更新**:
    *   `/idunn commit users/<player>/house1 "Added diamond block"`。
5.  **验证**:
    *   检查刚才放置的实例。
    *   **预期**: 实例中自动出现了钻石块。

## 3. 测试场景 B: 玩家修改保留 (保守更新)

**目标**: 验证玩家对实例的修改不会被模板更新覆盖。

1.  **准备**:
    *   继续使用场景 A 的实例。
2.  **修改实例**:
    *   在实例中，将一面木板墙打破，换成玻璃 (Glass)。
3.  **修改模板**:
    *   回到原模板选区。
    *   将那一面木板墙换成黑曜石 (Obsidian)。
    *   在另一个无关位置放一个金块 (Gold Block)。
    *   复制选区 (`//copy`)。
4.  **提交更新**:
    *   `/idunn commit users/<player>/house1 "Changed wall to obsidian"`。
5.  **验证**:
    *   检查实例。
    *   **预期 1 (冲突部分)**: 墙壁依然是 **玻璃** (玩家修改被保留)。
    *   **预期 2 (无冲突部分)**: 金块出现了。

## 4. 测试场景 C: 空方块填充 (Idle Blocks)

**目标**: 验证“空方块”能被模板的新内容填充。

1.  **准备**:
    *   放置一个新的实例。
    *   确保实例周围有一些空气。
2.  **修改实例**:
    *   在实例的空气位置放一桶水 (Water)。
3.  **修改模板**:
    *   在对应位置放一个石头 (Stone)。
    *   复制选区。
4.  **提交更新**:
    *   `/idunn commit ...`。
5.  **验证**:
    *   检查实例。
    *   **预期**: 水被石头替换了 (因为 Water 在 config 中被定义为 Idle Block)。
    *   *注*: 如果将 Water 从 config 中移除，则水应该被保留。

## 5. 测试场景 D: 结构空位 (Structural Void)

**目标**: 验证模板中的 Structural Void 不会覆盖实例。

1.  **修改模板**:
    *   在某个位置放 `minecraft:structure_void`。
    *   复制选区。
2.  **修改实例**:
    *   在对应位置放一个萤石 (Glowstone)。
3.  **提交更新**:
    *   `/idunn commit ...`。
4.  **验证**:
    *   检查实例。
    *   **预期**: 萤石依然存在 (模板说“这里是结构空位，忽略我”)。

## 6. 旋转与翻转测试

1.  **放置**:
    *   `/idunn place ... 90 true false false` (旋转 90度，X轴翻转)。
2.  **更新**:
    *   修改模板，提交更新。
3.  **验证**:
    *   新内容是否正确出现在旋转/翻转后的位置？
